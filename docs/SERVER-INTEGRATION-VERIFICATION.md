# 진행자–캐릭터 서버 연동 검증

검증일: 2026-10-27 (Asia/Seoul)

## 대상과 방법
로컬 `http://localhost:8000`의 진행자 화면 한 개와 캐릭터 화면 네 개를 실제 Firebase Realtime Database에 연결했다. 진행자 UI에서 새로 생성된 테스트 방 `TUGA`만 사용했다. 기존 사용자의 방에 입장하거나 데이터를 수정하지 않았다.

검증한 흐름: 진행자 단계 변경 → `mm/v2/rooms/TUGA`의 상태 저장 → 각 캐릭터의 구독 수신 → 조사/투표/캐릭터북 화면 반영 → 캐릭터의 선점·투표 → 진행자 집계.

서버 저장의 증거는 서로 다른 클라이언트의 실시간 반영 및 새로고침·재입장 후 복구다. Firebase 관리 콘솔이나 별도 서버 로그에 접근한 것은 아니다.

## 결과
| 항목 | 결과와 증거 |
|---|---|
| 방 생성·입장 | 진행자에서 TUGA 생성. 네 캐릭터가 같은 코드와 단계를 표시 |
| 중복 역할 | 별도 탭의 윤꽃집 재입장에 ‘이미 다른 사람이 맡은 인물입니다’ 표시. 기존 플레이어 정상 유지 |
| 조사 전 차단 | 오프닝에서 ‘아직 조사할 수 없습니다’, 카드 미개방 |
| 1차 조사 | 네 역할 모두 조사 진입. 기본 조사 기회 3회 |
| 동시 선점 | 1장 남은 윤꽃집 공간을 윤꽃집·한소설이 동시에 선택. 윤꽃집만 news 확보. 한소설 실패 후 기회 3회 유지 |
| 단서 소유 분리 | 최초 확보: 윤꽃집 news, 한소설 kakao, 백비서 envelope, 유감독 chat. 각자 단서함 1장 |
| 자동 보관 | 윤꽃집이 확인 버튼 없이 Escape로 닫아도 news 보관 |
| 사용 제한 | 한소설이 총 3장 확보하면 조사 기회 0회, 모든 더미 선택 비활성화 |
| 플레이어 새로고침 | 윤꽃집 새로고침 시 입장 화면 표시. 직접 재입장 후 news 1장·남은 기회 2회 복구 |
| 진행자 새로고침 | 롤카드 확인 단계에서 같은 방과 남은 시간 복구. 갱신된 질문형 캐릭터북 안내 표시 |
| 회의 조사 차단 | 1차·2차 회의에서 조사 미개방, 확보한 단서함은 유지 |
| 비밀 화면 위 투표 | 백비서의 비밀/화면 덮기를 닫고 자동으로 투표 화면 표시. 다른 세 화면도 투표 전환 |
| 1차 투표 | 선택만 하면 GM 0/4 유지. 제출 후 4/4, 네 인물 각 1표. 제출 후 변경 불가 |
| 투표 재입장 | 유감독 재입장 후 제출한 윤꽃집 지목 및 4/4 상태 복구 |
| 2차 조사 | 한소설 기회가 다시 3회로 열리며 기존 단서 3장은 유지 |
| 단계 종료 중 공개 카드 | 유감독이 2차 단서를 공개한 채 GM이 회의로 전환. 카드 창 닫힘, 누적 단서 2장 보존 |
| 최종 조사 | 새 조사 기회 3회, 기존 단서 유지. 캐릭터북의 조사 버튼에서 실제 조사 보드 진입 |
| 캐릭터북 행동 갱신 | 유감독 홈에서 2차 회의 ‘단서함 확인하기’ → 최종 조사 ‘조사 보드 열기’ → 최종 변론 ‘내 단서 확인하기’ 갱신 |
| 최종 투표 분리 | 1차 결과와 별도로 0/4에서 시작. 최종 4/4, 윤꽃집 3표·한소설 1표로 GM/플레이어 일치 |
| 진상 공개 | GM의 범인 확인 화면 진입. 캐릭터북에 ‘공용 화면에서 사건의 진상을 함께 확인’ 표시 |
| 콘솔 | GM·네 캐릭터의 수집된 오류/경고 로그 없음 |

## 발견해 수정한 부분
1. 진행자 롤카드 안내가 이전 탭 이름을 사용하던 문제: ‘내 역할 확인하기’와 질문형 읽기 흐름으로 수정.
2. 캐릭터북 홈의 주 버튼이 단계가 바뀌어도 대기 안내로 남던 문제: 실제 서버 phase에 맞는 현재 할 일과 이동 버튼 제공. 조사 → 조사 보드, 회의/최종 변론 → 단서함, 자기소개 → 예시. 서버 업데이트는 읽던 본문을 강제로 넘기지 않으며, 투표는 기존처럼 우선 전환한다.

## 추가 자동 검사
- `node tests/check-game.cjs`: 기존 방 덮어쓰기 방지·새로고침 정책·조사 제한·타이머, 새 게임 취소 및 확인 시 GM 세션만 초기화.
- `node tests/check-experience.cjs`: 카드 선점·공개·보관·전환 경합·확대·투표.
- `node tests/check-rolebook.cjs`: 인물 데이터 매핑·정보 범위·입장/투표와 캐릭터북 전환, 서버 phase별 행동 연결.
- 모두 통과. 자기소개 바로가기 매핑은 자동 검사로 확인했으며, 이번 온라인 실기에서 해당 바로가기 버튼을 따로 누르지는 않았다.

## 검증 범위와 남은 확인
- 같은 컴퓨터의 분리된 브라우저 탭 5개로 실제 서버를 검증했다. 실제 휴대폰 4대, 이동통신/Wi-Fi 차이, 장시간 네트워크 단절은 시험하지 않았다.
- 90분을 기다리지 않고 GM의 다음 단계 버튼으로 순차 진행했다.
- QR은 기존 공개 배포 주소 `https://isensmark.github.io/isens-mm/`를 가리킨다. 이번 로컬 수정본을 게시한 뒤 휴대폰 QR 접속을 확인해야 한다. 로컬 파일을 공개 배포한 것은 아니다.
- 새 게임 버튼의 추가 실기 검증은 브라우저 입력 제어 타임아웃 및 앱 확인창 조작 도구의 안전 제한으로 완료하지 못했다. 이를 통과로 기록하지 않는다. 제어가 멈춘 테스트 GM 탭은 닫았으며, 확인 후 새 방 생성·초기화까지 실제 UI에서 확인한 것은 아니다. 관련 세션 초기화·기존 방 보존은 자동 검사로 검증했다.
- 테스트 방 기록은 삭제하지 않았다. 사용자의 기존 방/배포/서버 권한 설정은 변경하지 않았다.
