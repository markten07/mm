# 역할과 비밀을 먼저 알고 기억을 읽는 순서

## 변경 이유와 흐름

플레이어는 과거와 사건 행적을 읽을 때부터 자기 역할의 입장을 알아야 한다. 기존 여섯 번째 비밀 확인을 첫 번째로 옮겼다. 전체 장면 수는 여섯 개로 유지한다.

기억 진입 연출 → 01 내 역할·비밀·대화 원칙 → 02~06 기존 다섯 기억 → 기억 수첩의 대화 준비.

첫 확인은 상세 문서 전체가 아니라 아래 세 가지로 제한한다.

- 내 정체: 기존 ME.verdict의 범인 여부.
- 나만 아는 행동: 원본 설정에서 본인이 한 살해 시도와 핵심 비밀.
- 대화할 때: 윤꽃집의 거짓 알리바이 허용과 다른 세 인물의 증거 추궁 시 사실대로 답하기를 구분한다.

윤꽃집은 물잔과 어긋난 표적, 한소설은 아내의 수프에 한 행동, 백비서는 사랑·편지·서재 물병, 유감독은 한소설과의 협력 및 홍대표 몫 과일청을 짧게 안내한다. 범인이 아닌 세 인물도 살해 시도가 있다는 것을 분명히 한다. 다른 인물의 비밀이나 실제 사망 원인을 새로 알려주지 않는다.

## 보호와 재확인

- 첫 역할 정보는 확인 버튼을 누르기 전 DOM에 렌더링하지 않는다. 가려진 동안 다음 버튼과 다른 기억 버튼을 잠근다. 이미 방문한 장면이 있어도 가려진 첫 역할을 진행 버튼으로 건너뛰지 못한다.
- 이후 다섯 기억에는 추가 잠금을 넣지 않는다. 마지막 만찬 장면에서 ‘대화 준비하기’로 수첩을 연다.
- 수첩 상단에서 첫 인사와 공통 대화 안내를 보여준다. 역할별 비밀과 답변 정책은 별도의 ‘내 비밀·대화 원칙 다시 확인’ 버튼으로 가려서 연다. 수첩에 범인 여부를 자동 노출하지 않는다.
- 화면 덮기, 이동, 투표 후 첫 역할 정보는 다시 가려진다. 조사·단서함과 미완독 수첩 접근은 기존처럼 유지한다.
- 진행자 본문과 안내 캐릭터, 독립 미리보기도 동일한 순서로 바꿨다. 초기 연출에 쓰는 그림 범위는 기존 본인 기억 그림으로 유지한다.

## 검증

- 실제 1~4.html 모두 01장면의 잠금/비밀 DOM 부재 → 해당 인물의 범인 여부·행동·대화 원칙 → 화면 덮기 후 재잠금 → 02~06 무잠금 진행 → 수첩 완료를 확인했다.
- 네 수첩 모두 대화 준비 영역이 있었고 범인 판정은 표시되지 않았다. 비밀 재확인 버튼은 별도 잠금 화면을 열었다.
- 한소설 독립 미리보기 역시 첫 확인 후 다섯 기억으로 완료되고, 수첩의 비밀 버튼은 01장면을 가린 채 열었다. 자동 검사는 미리보기와 실제 한소설의 요약 문구가 동일함을 확인한다.
- 390×844에서 첫 역할 화면을 확인했다. 320×568에서는 확인 버튼을 스크롤 없이 누를 수 있도록 간격을 줄였다(버튼 y=321.84~372.04, 읽기 영역 끝 y=404.5). 긴 공개 내용은 읽기 영역에서 스크롤되며 가로 넘침 없이 하단 메뉴/진행 버튼을 유지한다. 1280×800에서도 역할 내용이 읽기 영역 안에 들어오고 가로 넘침이 없었다.
- 별도 Firebase 시험 방 QQWX에 진행자와 네 인물을 연결했다. 윤꽃집이 첫 비밀을 연 상태와 한소설이 아직 잠근 상태에서 1차 투표를 시작했다. 역할북이 가려지고 공개된 비밀이 DOM에서 제거되며 투표 화면으로 전환됐다. 네 명 제출 및 진행자 4/4 집계를 확인했다.
- 2차 조사로 돌아온 윤꽃집의 첫 역할은 다시 잠겼다. 진행자 타이머를 일시정지하고 시험 탭을 닫았다. 다섯 서버 시험 화면의 warn/error 로그는 비어 있었다.
- 진행자 새로고침 후 같은 시험 방과 단계가 복원됐고, 최신 ‘첫 역할 확인 → 다섯 기억’ 안내가 표시됐다.
- 자동 검사 6종 및 사이트 빌드 통과. 장면 수, 순서, 초회/재방문 잠금 우회 방지, 일반 장면 완료, 인물 정보 범위와 기존 조사·투표 동작을 검사했다.

원본 ME·단서·조사 횟수·서버 진행 규칙은 바꾸지 않았다. 순서와 표현의 개선이며, 실제 사용자에게 역할 이해가 얼마나 빨라지는지는 플레이테스트로 추가 확인한다.
