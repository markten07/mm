# 빛나는 물체와 기억 진입 연출

## 경험

1. 실제 캐릭터 화면을 열 때 작은 빛이 먼 오른쪽 위에서 나타난다. 잔상을 남기며 가까워지고 인물 앞에서 감속해 머문다. 접근은 약 3.4초이며 버튼을 기다리게 하지는 않는다.
2. ‘기억 받기’를 누르면 물체가 화면 중심으로 이동하고, 인물의 얼굴·깊이의 고리·빛의 궤적과 해당 역할의 기억 그림 두 장이 스친다. 약 1.9초 후 첫 기억으로 이어진다.
3. 연출은 첫 진입 및 명시적 ‘기억 처음부터 다시 보기’에서 재생한다. 읽던 기억 이어보기나 조사·단서함 이동마다 반복하지 않는다.
4. ‘바로 기억 보기’는 즉시 첫 장면으로 넘긴다. ‘화면 덮기’는 전환을 취소하고 덮기 화면을 연다. 소리는 자동 재생하지 않는다.
5. 움직임 줄이기 및 OS의 모션 감소 설정에서는 기다리는 전환 없이 첫 기억으로 이동한다.

기존의 돌은 가려진 입장 화면 뒤에서 애니메이션이 소모될 수 있었다. 새로운 비행은 실제 역할북이 보일 때 시작한다. 그 이후 UI가 다시 그려져도 도착한 물체로 유지한다.

## 구현과 게임 연결

- `memory-portal.js/css`는 네 역할과 독립 미리보기에서 공유한다. 비행·전환은 HTML/CSS/SVG로 만들며 영상 파일이나 새 이미지 생성은 필요하지 않다.
- 그림 조각은 해당 역할의 기존 기억 그림 최대 두 장만 사용한다. 다른 인물, 마지막 범인 여부 및 새 단서는 넣지 않는다. 전환은 그림 다운로드 완료를 기다리지 않는다.
- 역할 읽기 완료나 장면 이동은 연출 완료/명시적 건너뛰기 때만 실행한다. 반복 클릭은 한 번으로 처리한다.
- 화면 덮기, 탭/역할 화면 이탈, 서버 투표는 진행 중 연출과 타이머를 취소한다. 취소된 완료 콜백은 나중에 화면을 바꾸지 않는다.
- 전환 중 기존 콘텐츠는 inert로 처리하고 두 조작 버튼만 사용한다. 취소·완료 때 inert를 복원한다. 버튼 사이 Tab 이동 및 Escape 건너뛰기를 제공한다.
- 캐릭터 사실, 단서 데이터, 조사 및 투표 규칙은 바꾸지 않는다. 기존 마지막 정체 확인 절차도 유지한다.

## 검증

- 네 실제 역할 모두 입장 전 비행 클래스 0 → 입장 후 1 → 전환 표시 → 즉시 건너뛰기 → 01장면을 확인했다.
- 실제 한소설 화면과 독립 미리보기에서 자동 전환 종료 후 01장면 진입을 확인했다.
- 기억 수첩에서 재생 중 ‘화면 덮기’를 선택하면, 타이머 종료 후에도 첫 장면으로 바뀌지 않고 수첩으로 복귀했다.
- 실제 ‘움직임 줄이기’ 상태에서는 전환 화면을 띄우지 않고 즉시 01장면으로 들어갔다.
- 390×844 모바일에서 비행과 진입을 확인했다. 320×568에서 전환 화면의 가로 넘침 없이 건너뛰기 가능, 1280×800에서도 화면 크기에 맞는 전환과 버튼 위치를 확인했다.
- 서버 시험 방 7DGM에 진행자와 네 인물을 연결했다. 윤꽃집의 전환이 표시된 도중 1차 투표를 시작해 즉시 투표로 넘어갔다. 네 명이 제출했고 진행자가 4/4를 집계했다.
- 2차 조사로 넘어간 뒤에도 취소된 연출이 첫 기억을 뒤늦게 열지 않았다. 원래 첫 화면을 가린 상태로 돌아왔다. 타이머 일시정지 후 시험 탭을 정리했다. 다섯 시험 화면의 warn/error 로그는 비어 있었다.
- 자동 검사 6종과 정적 빌드 통과. 연출 검사에는 중복 클릭, 취소 후 늦은 타이머, 건너뛰기 중복 실행, 화면 덮기, 모션 감소 및 이미지 범위를 포함했다.

실제 휴대폰 GPU에서의 부드러움과 체감 몰입도는 사용자 플레이로 추가 확인한다. 정적 스크린샷은 움직임 전체를 대신하지 않으므로 미리보기의 ‘기억 받기’를 눌러 확인한다.
