# 진행자 화면 개선 검토

작성일: 2026-11-03. 검토 요청에 대한 분석 문서이며 게임 구현은 변경하지 않았다.

## 범위와 근거

- 현재 `index.html`, `assets/host-guide.js`, `assets/host-guide.css`, `assets/visual-upgrade.js`, `assets/room-qr.js`, 플레이어 입장·단계 연동 코드 검토.
- 기존 서버 연동 화면 기록 `screenshots/integration-final-votes-gm.png`와 이전 검증 문서 참고.
- 독립 오프라인 복사본의 새 브라우저 검증은 file URL 접근 정책에 의해 차단됨. 우회하지 않았으며 이번 검토에서 신규 4인 플레이·모바일 실기 검증을 수행했다고 간주하지 않는다.
- 아래 동작 문제는 코드로 확인한 사항이고, 이해도·몰입도 개선 효과는 이후 사용자 테스트로 검증할 설계 가설이다.

## 총평

현재는 프롤로그·진상 이미지/음성 재생, 단계별 안내, 타이머, 투표 집계, 방 복구 등 기본 진행 기능이 있다. 다음 개선의 중심은 참가자 상태와 전환 조건을 보여주는 진행 도구다. 담당 형사 대사만 늘리면 읽을 내용과 화면 높이가 늘 수 있다.

## 우선순위 1: 게임 진행에 직접 영향을 주는 동작

### 1. 투표 공개 시점

`paintVote()`는 전원 제출 전에도 인물별 득표수와 투표자 이름을 출력한다. 뒤에 제출하는 사람이 앞선 선택을 볼 수 있으므로 현재의 동시 투표 안내와 맞지 않는다.

제안: 제출 중에는 제출 여부와 0/4~4/4만 표시. 전원 제출 후 결과 공개 동작을 제공. 최종 진상 진입도 전원 제출 조건으로 검사한다. 공개 투표자 이름은 현행 규칙을 유지하더라도 제출 완료 이후에만 보인다.

### 2. 시간 종료와 단계 종료 분리

`run()`은 모든 단계에서 시간이 0이 되면 `startRound(ri+1)`을 실행한다. 수동 다음 버튼도 완료 조건이 없다. 따라서 투표 미완료 상태에서도 진상 대기로 이동할 수 있고, 대기 화면의 “모든 투표가 끝났습니다”는 실제 상태를 보장하지 않는다.

제안: 기본은 시간 종료 알림 → 현재 화면 유지 → 진행자가 연장/다음 단계 선택. 특히 투표는 전원 제출을 조건으로 한다. 일반 단계 자동 진행은 필요할 경우 명시적인 선택 기능으로 제공한다. 4명 미만인 경우를 정상 완료로 표시하지 않는다.

### 3. 참가자 상태와 서버 반영 확인

GM은 투표만 실시간 구독하며, 인물별 입장·준비·조사 상태를 집계하지 않는다. 플레이어의 `players/{role}`에는 역할 점유 토큰이 있지만 현재 접속 상태나 준비 완료를 뜻하지 않는다. GM의 ONLINE 값도 실시간 연결 건강 상태와 같지 않고, `pushRound()`의 쓰기 실패는 사용자에게 보이지 않는다.

제안: 역할 확보, 현재 연결, 사용자가 누른 준비 완료를 각각 구분한다. 역할 읽기는 자동 완독 추정 대신 준비 완료 버튼을 우선 사용한다. 서버 반영 중/완료/재연결 중을 표시하고 단계 반영 실패 시 재시도할 수 있게 한다. 공용 화면에는 비밀·선택한 단서·투표 대상을 준비 상태로 노출하지 않는다.

## 우선순위 2: 진행 중 판단과 조작

### 4. 한 화면의 정보 우선순위

단계 설명, 담당 형사 대사, 지금 할 일, 진행 안내가 유사 내용을 반복한다. 기존 1280×720 투표 화면 기록에서는 주요 진행 버튼을 보려면 내부 스크롤이 필요했다. 현재 짧은 높이 CSS는 규칙 상세·다음 단계 등을 숨긴다.

제안: 현재 단계 / 이번에 할 일 한 문장 / 타이머와 참가자 상태 / 고정 진행 버튼 순서. 상세 규칙과 읽어줄 대본은 필요할 때 펼친다. 규칙 정보는 화면 높이에 따라 사라지지 않도록 한다. 공용 화면의 큰 텍스트와 운영 버튼은 대비와 위계로 구분한다.

### 5. 진행 버튼의 의미와 복구

상단 “새 게임 시작”과 하단 “처음으로”가 같은 새 방 생성 동작이다. “이전 단계”는 그 단계의 시간을 다시 시작하지만 단서·투표를 되돌리지 않는다. “일시정지”는 GM 타이머만 멈추며 플레이어 조사 잠금을 전파하지 않는다.

제안: “처음으로”를 제거하고 새 게임은 설정 영역에서 명확하게 제공. 되돌아보기와 실제 단계 변경을 구분하고, 실제 변경 시 보존되는 단서·투표를 안내한다. 현행 기능을 유지하면 버튼은 “타이머 멈춤”으로 명명한다. 전체 게임 중지는 서버 상태 및 플레이어 동작까지 함께 설계할 때만 제공한다.

### 6. 회의 진행 지원

자기소개와 최종 변론은 1인 1분 30초 안내가 있지만 실제 타이머는 단계 전체 6분만 표시한다.

제안: 현재 발언자, 다음 발언자, 개인 타이머와 다음 사람 버튼. 회의 화면에는 “단서 이름 → 확인할 사실 → 상대 답변” 등 대화를 시작할 짧은 틀을 제공한다. 의심 대상이나 정답 방향은 자동 추천하지 않는다.

## 우선순위 3: 연출·마무리

### 7. 시각·음성 일관성

캐릭터 화면의 단정한 톤과 GM의 보라색·금색·별도 형사 일러스트 톤이 다르다. 음악, 분위기, 내용 듣기, 장면 재생이 따로 있어 음성 기능의 역할을 파악하기 어렵다.

제안: 캐릭터 화면과 타이포·버튼·간격을 공유하되 공용 화면은 더 큰 글씨를 사용한다. 형사는 단계 전환 시 짧게 등장하고 상시 큰 안내 상자는 축소한다. 음성은 배경음/나레이션 설정으로 정리하고, 현재 재생 중인 소리의 상태를 표시한다. 자동 재생과 진행자 직접 읽기 선택을 명확히 한다.

### 8. 추가 증거 및 종료 후 회고

추가 증거는 최종 조사 진입 시 미획득 목록을 한 번 읽는다. 이후 참가자가 가져간 단서가 목록에 남을 수 있고, 공개 이력은 메모리 변수에만 있어 새로고침하면 사라진다. 진상 공개는 시각 자료가 있지만 이번 팀의 실제 발견·투표 기록과 연결된 회고는 없다. 프롤로그·진상 장면 위치도 GM 복구에 저장되지 않는다.

제안: 추가 증거 공개 시 현재 확보 여부를 다시 확인하고 공개 이력을 방에 저장. 진상 공개 후 이번 투표, 핵심 증거, 각 인물의 행위가 연결된 짧은 회고를 제공한다. 재생 위치 복원 또는 시작 위치 선택을 제공한다. 동점·미제출 판정은 별도 규칙 확정 없이 임의로 추가하지 않는다.

## 권장 화면 구성

1. 준비: 역할별 입장 현황, QR, 소리 확인, 조사 횟수 설명, 시작 버튼.
2. 진행: 현재 단계와 한 문장 안내, 타이머, 단계에 맞는 상태(준비·조사·투표), 고정 조작 영역.
3. 상세 도구: 전체 게임 순서, 규칙, 읽어줄 대본, 방 관리. 한 기기에서도 사용 가능하게 접힘 패널로 제공.
4. 진상: 전원 투표 확인, 결과 공개, 진상 재생, 이번 게임 회고.

권장 순서: 투표·전환 조건 → 상태 집계·연결 안내 → 레이아웃·버튼 정리 → 발언 지원 → 연출·회고.

## 이후 검증 기준

- 0/4 및 3/4 투표에서 시간 종료·다음 버튼으로 결과/진상이 공개되지 않는지.
- 4/4 제출 전 타인의 투표 대상이 공용 화면에 보이지 않는지.
- 준비 완료를 누르지 않은 사람을 완료로 표시하지 않는지.
- 네트워크 단절과 복구 시 진행자가 서버 반영 상태를 구분하는지.
- 이전 단계로 돌아가도 단서·투표 보존 여부가 안내와 일치하는지.
- 1280×720 및 작은 모바일 화면에서 주요 조작과 필수 규칙을 찾을 수 있는지.
- 처음 진행하는 사람이 별도 설명 없이 입장 확인, 단계 진행, 시간 연장, 결과 공개를 수행할 수 있는지.
